# 生产约束的边界与调整规则

每个完成的父阶段只等待用户一次五分钟。一个制作目标的计划小修继承已有 S1 窗口身份、截止时间和用户指令，展示最新的完整计划文档；保存草稿和应用修订均不能反复延长等待。公开测量按同源文件路径、大小和修改时间缓存原生输入及传感器附件，保留真实尺度、物理与生活验收要求。

约束应服务于用户的制作目标。真实资产是默认方案；用户保存的计划明确声明简化几何实验时，按该实验的测量条件生产。模型不能自行降低用户要求，也不能把设计参考、准备稿或测试夹具冒充真实捕获、标注、GT 或生产验收。

保留原生捕获来源、实际支撑与碰撞证据、生活布局合理性、公开题面可回答性、模板测量条件和评分合同。视觉意见与物理测量分别记录；一个视角看不见某个物体时，结合其它机位和执行证据判断。修复应围绕真实缺陷进行，记录场景标题、摘要、修改和未解决问题，并用后续捕获校正设计摘要。

以下约束按其实际目的实现：

| 项目 | 行为 |
| --- | --- |
| 场景观察文字 | 必须是非空文字并引用真实机位；不以八个字符等任意字数代表证据充分性。保留检查项、机位覆盖与物理检查。 |
| 计划 Markdown 编辑 | 保留整个用户文档。排版变化不要求重写制作步骤；真实制作规则变化必须落实到步骤或证据输入。 |
| 计划文件传输 | 应用指令读取 edit_revision.base_plan。显式 YAML 已改变时保留保存后的结构数据；只有正文规范化才提交 markdown_resolution。完整可执行请求保存一次并用 request_path 提交；旧会话尚未公布该参数时用生产 Python 调用 integrations/spatialforge/ui/plan_request_cli.py，保留相同计划校验与会话来源。重复应用同一准确请求不新建计划或重开审阅窗口，不能以旧工具定义为由重新抄写大文档。 |
| 删除计划文字 | 字段解析可引用新正文的新增文字，也可引用确已从旧正文删除的原句。字段前后值与映射覆盖必须精确，未映射删改继续阻断应用。 |
| 路径身份 | 同一计划文件的规范化路径视为同一身份；未应用的修改和真正切换计划继续阻断旧流程。 |
| 用户等待 | 每阶段实际产物验收后开一次五分钟窗口。待应用草稿和子任务准备不额外开窗口；单次等待默认六十秒返回状态，原截止时间不重置。 |
| 采集等待 | 父会话用 spatialforge_wait(background=true) 为当前 run 注册一次后台观察，继续独立工作或结束本轮；运行时有界长轮询，终态或观察错误只唤醒原会话一次。收据保存在 runtime/capture-watches。进程退出会中断观察，收据保留状态；重新调用可恢复，不把后台受理当作采集完成。 |
| 昂贵候选计算 | 先执行便宜的可见性和协议过滤，再逐个执行真实 oracle；达到计划配额且实际验收通过后停止。只有计划需要全局排序或总体分布时才穷尽昂贵候选。三角面距离仍由原生三角面计算，包围盒只能用于过滤。修复失败题时复用其余合格题及证书，记录真实候选、写出、验证和发布计数；心跳不增加完成数。 |
| 公开测量附件 | 题面声明的标定、深度、掩码和局部轴附件随公开包一起交付，保持可解析的相对引用，共享文件只复制一次。工作台可打开或下载这些附件；私有 GT 只进入 authority。 |
| 公开中心与计数范围 | 中心距离题先确认公开深度、标定和掩码足以在原有误差界内恢复对应原生中心，再采样对象。计数范围必须在题面和编号图中明确，并与公开掩码一致；保留不能充分观测的对象在真实场景中，按题目的明确范围选用它们。 |
| 排序题与计划阈值 | 按已应用计划用原生未取整距离检验相邻名次差，严格大于与至少分别执行。公开候选顺序按保存的 seed 打乱并与正确排序解耦，题面、编号图、公开参数与私有答案保持对应；修复公开列举顺序不重算已通过的几何证书。 |
| 题目原生身份与发布 | evidence 从已验收捕获回执绑定真实 task/run、计划版本和场景，逻辑场景名称不能替代原生身份。写出、公开测量通过、制作条件通过、修复候选通过和正式发布分别计数；仅 Runtime 接纳并可读取的正式数据集计为已发布。 |
| 源证据分区 | 默认按请求的单一分区生产。计划显式启用 preserve_source_splits 时保留每条源证据及其场景组的分区，报告真实分区题数；SFT 只含 train，混合评测集合不导出训练包。 |
| 当前生产会话提速 | 用户要求提速时，工作台可信 execution_control 只调整当前工作区的父会话，先查询当前模型实际支持的档位，允许选用已公布的 off/low/medium 等轻量档；保留模型路由、输出上限、质量要求与 Host 默认。部署配置必须把档位转换为服务端实际接收的字段；仅发送开启推理布尔值时，不能宣称 high 比 max 更快。通过公开 agent/request 在下一请求边界调整一次，request/header 才证明生效；后续原生模型选择不被强制覆盖。仅切档保留已有 compact 回执。历史压缩使用公开原生能力：步骤边界 compactRegion 保留系统提示、至少 32768 token 的近期尾部与完整工具调用/结果配对；隔离预设无法直接访问该服务时，等空闲后调用已注册的 /compact，使用其原生摘要、配对检查和维护锁。两者均保留持久回执，不伪造 overflow、不截断当前工具或取消采集。当前工作区 .benchforge/execution/<session>.json 保存受理、生效与压缩结果。 |
| 模型与工具耗时 | execution_status 根据原生步骤、请求、消息及配对工具事件区分准备、模型、工具和压缩，显示本次活动已经消耗的时间。最近完整模型步骤分别记录总耗时、首段流等待、输出生成速度和是否仅有推理内容；无流时间证据时速度为未知。仅推理且没有工具动作的回复不算产物或生产完成，不展示私有推理正文。压缩是否提速须看后续实际输入和耗时，不能只凭压缩受理或旧累计统计。 |
| 视觉评审证据 | 物体存在、朝向和用途应结合相关机位、已捕获的原生身份及最终姿态核对。单个视角被遮挡不证明对象缺失；已入镜的书和杯子不能被“空桌面”的文本意见抹掉。柜顶作为收纳平面等正常用途按用户计划判断，不因同义描述否决；真实功能冲突、物理缺陷和题面缺少必要可见信息仍须修复。描述稿的计数或用途矛盾按授权修订，保护硬要求，并通过正式接口保存和重新验收实际变更。 |
| 资产正面与功能朝向 | `native_asset_facing.json` 记录经过原生网格核对的资产正面及源 USD，规划辅助 `native_asset_facing.py` 按目标位置计算 yaw。显示器面向操作者、办公椅面向工作对象、会客座椅面向谈话目标；不能把资产包围盒的长边、某个默认轴或图像评审通过当作资产正面证据。未知资产保持未校准，不能自动套用已知资产的轴。校准只用于对应源资产的规划；后续实际姿态、支撑与通行仍按新采集验收。 |
| 采集故障恢复 | /retry 按真实失败阶段检查。已入队的冻结程序尚未采集时仍可恢复；auto 在没有完整采集确认时创建新 attempt，保持原 task/revision，保留旧尝试。完整原生采集只恢复上传和 offset，不重做场景。local_capture_preserved 不证明采集完整；质量失败、取消或已成功任务不能借恢复跳过验收。 |
| 准备任务推理 | 通过 spatialforge_prepare 或工作台可信适配器查询继承模型的真实支持列表，优先选择受支持的 low，再按公开列表回退到较轻档位。未公开推理控制时不传档位覆写，记录 inherit/not_applicable 的理由。收据保留支持列表、实际档位和选择原因。保持 provider/model、父推理与 Host 默认，不给 worker 额外短输出上限，不虚构或隐瞒实际档位。旧会话的参数开关不影响可信适配器；普通原生委派不再强制不受支持的档位。 |
| 并行预算 | 默认一批三个，可由可信部署配置调整；场景设备仍使用其真实队列。只根据实际运行状态计算准备任务占用，启动受理不等于生产完成。 |
| 工具隔离 | 使用父会话实际注册的工具名称；缺失的可选工具不应让所有委托失败。计划应用、采集、验收与打包由父流程负责。 |
| 准备交付与验收职责 | 保存修补文件、必要检查和诚实清单即可交接准备稿；缺失生产输入写入阻塞项。只读准备子任务观察旧捕获，不会因此承担父级采集和修复验收。实际生产者仍须完成原有验收。 |
| 检查成本 | 严禁复杂 SHA 检查，不对全部输入、PNG、输出和回执批量算哈希。沿用已有原生身份，必要的版本绑定记录大小与 mtime。JSON/JSONL 正常序列化后不逐条读回做重复检查；只检查本次改动、实际失败和必要的生产边界。不得反复全目录扫描、轮询未变化状态或重验无关已完成阶段。 |
| 标注与题目来源 | 标注保留真实原生捕获与验收的版本绑定，题目生成先验证其标注回执和仍有效的源场景验收。模板默认记录 media_versions 与 oracle_trace_ref，不要求每题计算图片或 oracle 的 SHA；已有原生 hash 可作为不透明元数据沿用。正式数据保留题面、测量、评分、配额、seed 与 split。 |
| 隔离测试 | 隔离测试目录可使用 smoke 路径组件或明确的 non_production 标记，不能仅因目录名称不同拒绝测试。测试回执和输出标为非生产，失败验收保持失败；正式出题和主流水线导入均拒绝明确的测试标记及未通过的源场景，不提升测试产物为生产。缺少测试标记的正常旧证据继续按原合同读取。 |
| 题面版本兼容 | 新题面写出当前 schema。完整旧题面仅缺版本标签时，先按原参数、测量规则、逐项媒体和公开文字合同校验，再在展示结果中补充当前版本；不改源题面或已通过的几何证据。显式不支持的版本仍拒绝并说明版本原因，不误报为缺失题面。当前正式入库状态优先于生成结束状态，失败原因直接展示。 |
| 原生活动与恢复 | inactive 和 Agent.status=idle 均不能证明活动真正结束；idle 可能仍包含 maintenance。只对当前父会话及其已关联子会话使用公共 whenIdle 做有界只读诊断，未结束的探测不重复叠加。未知状态和错误如实展示，诊断不自动取消任务或改变生产验收。必要恢复仅针对已确认卡住的当前父会话或直接子会话，保留文件、计划、已提交采集与收件箱。取消受理不代表恢复，应确认旧等待结束及新执行步开始；继续指令使用新的请求身份，避免去重成旧消息。 |
| 已授权制作与提问 | 子任务失败、准备稿整合、串行/并行调度，以及不降低硬要求的软摘要或引用修正，不需要重复提问是否继续。父流程复用当前交付，缺失输入只暂停依赖步骤；冻结快照不禁止父流程通过正式接口保存获授权的修订。只为真实缺失的用户信息或未授权的硬要求变更提问。ask_user_question 未答复时应报告等待用户，不能拿 running、消息入箱或旧失败批次当生产进展，也不能替代阶段的五分钟窗口。 |
| 状态展示 | 优先显示实际活跃和较新的子会话，保持有界读取。已关联的实际准备脚本、摘要和清单可直接打开，标明待合并与验收；不把空闲或文件存在当成生产通过。失败场景仍展示保留的证据与修复原因；缺失回执不推断成功。 |
| 修复循环 | 在用户预算内根据证据改善继续修复。连续无改善时报告具体阻塞，不按固定两次就放弃可修复场景。 |

外部原生接管使用工作台 `synthesis_start`/`synthesis_status` 入口，绑定当前父会话、其已保存计划及同工作区的独立输出目录。它保存批次身份和子会话受理回执；重复请求复用相同身份，异常启动先核对官方父目录和会话头。原生 spawn 继承父工作目录；专属输出目录是执行约定和产物核验范围，不应宣称为操作系统沙箱。

增量准备任务优先使用当前模型支持的 low 档；缺少 low 时从实际公布的较轻档位中选择，再回退到 medium/high 等可用档。父会话的模型选择保持独立。Qwen3.8-Flash-Next 的当前 OpenAI 接口已验证支持 `reasoning_effort=none/low/medium/xhigh`：外部 provider 配置用 `thinkingFormat: openai` 与 `off: none`、`low: low`、`medium: medium`、`high: xhigh`、`max: xhigh` 映射，保留已有默认选择。旧 `qwen-chat-template` 分支只发送 `enable_thinking`，不传低/中/高档位，不用于这些档位的性能判断。

热更新保留已运行会话的预设版本。工作台和新版模型状态工具对旧服务的确切 `400 KeyError('report')` 使用一次只读快照与保留的原生文件恢复显示，保持失败状态，不占用设备、不更改队列或验收结果。其它错误原样返回，用户取消仍及时终止。新的服务源文件供独立 Python 调用和后续正常服务重启使用；旧会话继续使用其绑定版本，必要时通过 `status(detail=true)` 读取保留状态。

长会话的原生交接摘要应保留当前目标、用户硬要求、有效产物、未完成作业及一个下一步动作，目标总长约 1500 token。旧版本、重复失败和完整代码引用保存路径及台账；不在摘要中逐次复制。可信提速适配仅为当前已授权的辅助 compaction 请求补充该要求，保留历史缓存前缀、模型路由及原生输出回执；普通 Agent 请求与用户消息不被改写。超时或原生摘要未提交时继续显示失败，不能声称历史已经缩短。
