# 工作台通用展示要求

计划、场景、标注、题目、报告五页保持现有风格，优先展示真实图片、可直接播放的视频或可操作全景，以及帮助用户判断和操作的有效文字。

- 正文、卡片和表格使用可读名称、用途、题目、数量、状态、规则及结果。技术 ID、运行编号、任务编号、协议编号、文件路径和原始 JSON 放入折叠详情，不占据主要区域；作答所必需的对象标记保留。
- 计划先展示目标、真实参考场景图片、题型名称和分配数量，再展示可直接修改的规则。参考图片注明来源性质，未采集的设计不得冒充已完成场景。
- 场景以一个项目一个场景展示名称、图像/视频、复选框和可用状态。历史与当前场景共用场景库。
- 标注优先展示配对场景图、标注图层、可见对象及必要单位；原始数据保留在详情。
- 题目区始终以网格展示多题缩略图、简短题面和题型名称，保留筛选与分页。点击卡片在弹窗中显示完整题面和公开媒体，关闭后回到原网格，不用单张大图替换列表。报告优先展示实际结果、质量检查、分布和缺口。未执行的结果不能标成完成。
- 提示文字保持简短、弱化层级。移除各页“生产记录”选择器；执行进度使用已有进展区。
- 正文编辑保存后形成新的活动计划，更新题量等制作输入；文字规则必须落实到制作代码和步骤。旧计划不能绕过已保存修改继续执行。

题目生产必须遵守 pipeline_catalog 返回的 question_authoring 合同。题干简短、直接，已知条件、测量规则、选项和作答方式分别展示；必要条件默认可见。来源证据必须提供 question_spec，并绑定准确原参数；生产入口校验后保存 question_presentation，同时生成包含完整条件的文本题面用于导出和训练。对象称呼必须能对应公开图片；按中心或采样点作答时，图中要有相应标记。保留准确模板的目标、参照系、单位、容差与输出合同。禁止内部路径、采集代码、原始 JSON 和未解释的协议术语挤入题干。程序检查不等于人类可回答性验收，仍须逐模板查看真实题面和公开媒体。
