# 工作台通用展示要求

计划、场景、标注、题目、报告五页保持现有风格，优先展示真实图片、可直接播放的视频或可操作全景，以及帮助用户判断和操作的有效文字。

- 正文、卡片和表格使用可读名称、用途、题目、数量、状态、规则及结果。技术 ID、运行编号、任务编号、协议编号、文件路径和原始 JSON 放入折叠详情，不占据主要区域；作答所必需的对象标记保留。
- 计划先展示目标、真实参考场景图片、题型名称和分配数量，再展示可直接修改的规则。参考图片注明来源性质，未采集的设计不得冒充已完成场景。
- 场景以一个项目一个场景展示名称、图像/视频、复选框和可用状态。历史与当前场景共用场景库。
- 标注优先展示配对场景图、标注图层、可见对象及必要单位；原始数据保留在详情。
- 题目区始终以网格展示多题缩略图、简短题面和题型名称，保留筛选与分页。点击卡片在弹窗中显示完整题面和公开媒体，关闭后回到原网格，不用单张大图替换列表。报告优先展示实际结果、质量检查、分布和缺口。未执行的结果不能标成完成。
- 提示文字保持简短、弱化层级。移除各页“生产记录”选择器；执行进度使用已有进展区。
- 正文编辑保存后形成新的活动计划，更新题量等制作输入；文字规则必须落实到制作代码和步骤。旧计划不能绕过已保存修改继续执行。

题目生产必须遵守 pipeline_catalog 返回的 question_authoring 合同。题干简短、直接，已知条件、测量规则、选项和作答方式分别展示；必要条件默认可见。来源证据必须提供 question_spec，并绑定准确原参数；生产入口校验后保存 question_presentation，同时生成包含完整条件的文本题面用于导出和训练。对象称呼必须能对应公开图片；按中心或采样点作答时，图中要有相应标记。保留准确模板的目标、参照系、单位、容差与输出合同。禁止内部路径、采集代码、原始 JSON 和未解释的协议术语挤入题干。程序检查不等于人类可回答性验收，仍须逐模板查看真实题面和公开媒体。

场景生产默认使用真实可辨识资产。模型在保存的计划中通过 scenes.geometry_exceptions 明确声明测量目的、简化原因、具体物体及范围、保留约束和不声称的能力时，允许简化几何实验。场景程序须在 provenance.sources 引用该 scene_plan 和设计标识，例外不跳过物理与逐图验收；生活合理性按实验设定判断。前端标明“简化几何实验”，优先展示目的和有效说明。提交完整场景程序后先通过 scene-library/policy.json 的准入检查，再采集、看图验收、标注和出题。历史删除场景及其派生产物不得重新导入、勾选或复用；素材不足时报告缺口，不能未经保存计划声明自动降级。计划声明修改后须重新验收，已删历史场景保持删除。墙体、地板等正常结构不按立方体目标处理。

无人值守必须实施服务端强制验收：真实可辨识资产与尺寸比例、支撑和重力、原生碰撞体与沉降、穿插待解风险、通行操作空间、房间用途与物品布局、材质采光分别留证。生活合理性采用实际逐图观察，物理仅引用原生执行测量；静态 stable=true、模型说合理、仅渲染成功均不足。capture_only 同样受控，未通过或证据变化不得成功、选用、出题或导出。最多两次修正后报告失败与缺口，保留证据。历史未验收场景可以预览，复选框禁用并显示待验收；不能把它们展示成已通过。

每个场景先保存标题及200到400字详细摘要，明确用途、布局、主要物体角色、朝向、支撑安装、通行与取用关系、光照和物理假设。用户硬要求单独保护；软设计可依据实拍双向迭代，每次记录观察、原因、改动和未解问题。生产必须对照摘要执行并对照全部实拍验收，摘要修订不能代替程序修复和重新采集。前端优先展示标题、摘要和有效修改依据，技术标识折叠。scene_brief.json 和 scene_brief_alignment.json 保存设计与观测对齐证据；版本变化使旧验收失效。固定安装必须有真实目标和几何连接，零件组成的桌椅需按实际零件表面检查支撑，不能把空心家具的整体包围盒当实心物体。

生活真实性按人的实际活动检查：椅子朝向与腿部空间、门柜开启范围、取用高度、工具操作区、连续通路与安全余量。物理检查覆盖沉降、实际动作轨迹和动作后的姿态与支撑，动作失败不能只靠动作前 stable=true 放行；不得悄悄移除交互或降低用户硬指标。已知采集父版的冻结摘要必须继承，不能省略版本引用逃过硬要求保护。

空间描述明确参照系：世界坐标、固定机位或使用者视角必须写清，不能随摄影机换位更改左右前后。相机位置与实际视图逐一对应供复核。资产颜色、材质和形态根据原生资产及实拍描述；软设计误写可以附证据修订，真实缺陷仍须修改程序并重新采集。自动修复从实际上一采集继承完整程序、冻结摘要、硬要求及历史，不能从旧草稿回退。
